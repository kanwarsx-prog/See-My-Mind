1. See_My_Mind_Technical_Blueprint_v0_2_Expanded.pdf / .pptx

What it contains:
A high-level technical design for the overall See My Mind platform. It covers the user interface, mobile and browser applications, Frappe application layer, workflows, database, security, privacy, multi-tenancy, user roles, reporting, dashboards, data import/export, AI/RAG and the broader technology architecture.

Who it is for:
Developers, technical volunteers, architects, potential delivery partners and anyone who needs to understand how the overall system should be structured.

Why it has been created:
To make sure everyone is working towards the same technical direction and that different parts of the product are not designed independently or inconsistently.

Purpose:
This is the main technical blueprint for the platform. It provides the overall architecture against which development decisions, estimates and technical discussions can be made.

2. See_My_Mind_Data_Model_v0_1.xlsx

What it contains:
The proposed database and data structure for See My Mind. It identifies the main objects and tables the application will need, the important fields, primary and foreign keys, and the relationships between them. This includes schools, children, guardians, staff, assignments, events, observations, incidents, support strategies, EHCP information, consent, documents, AI/RAG data and other supporting records.

Who it is for:
Developers, database designers, architects and anyone building or integrating the application.

Why it has been created:
Because the application needs a consistent underlying data structure before different features, workflows and reports can be built reliably.

Purpose:
This is the blueprint for how See My Mind stores and relates its information. It should become the basis for the application’s database schema and the Frappe objects that are created.
